# RushLab — Agent Guide

Agent-driven traffic scenario lab for the **San Ysidro border approach, Tijuana**.
Loads the street network from OpenStreetMap, simulates rush-hour traffic in SUMO,
finds bottlenecks with graph algorithms, optimizes signal timing, and reports
ranked scenario comparisons.

## Architecture map

- `src/rushlab/network/` — OSM ingestion, graph construction, graph metrics (networkx)
- `src/rushlab/demand/` — demand estimation and calibration (BTS volumes, CBP wait times)
- `src/rushlab/sim/` — SUMO runner, TraCI control, scenario execution
- `src/rushlab/signals/` — signal timing models and optimizers (Webster, GA)
- `src/rushlab/report/` — HTML/JSON report generation
- `src/rushlab/mcp_server.py` — MCP server exposing domain tools to agents
- `evals/` — reproducible agent benchmarks (Graphify tokens, plan vs execute, skill efficacy)
- `docs/decisions/` — ADRs: every scope or methodology decision, with assumptions

## Commands

```bash
uv sync --extra dev        # install environment (Python 3.12 managed by uv)
uv run ruff check .        # lint
uv run ruff format .       # format
uv run pyright             # type check
uv run pytest              # tests
uv run rushlab --help                      # CLI
uv run rushlab areas                       # list study areas
uv run rushlab build-area san-ysidro       # fetch + build analytic graph
uv run rushlab analyze san-ysidro          # bottleneck analysis -> results/
uv run rushlab demand san-ysidro           # BTS/CBP fetch + sink calibration
uv run rushlab sim-network san-ysidro      # build the SUMO network
uv run rushlab simulate san-ysidro         # baseline microsim -> results/
uv run rushlab optimize-signals san-ysidro # Webster + GA offsets -> signal file
uv run rushlab report san-ysidro           # scenario comparison -> HTML report
uv run rushlab-mcp                         # MCP server (stdio) for agent tools
uv run python -m evals.graphify_tokens     # benchmark: graph context vs raw files
uv run python -m evals.plan_vs_execute     # benchmark: plan vs direct (paid agent runs)
uv run python -m evals.skill_efficacy      # benchmark: skill impact (paid agent runs)
uv run python scripts/sync_agent_config.py # regenerate per-tool agent files
uv run python scripts/agent_doctor.py      # verify agent setup
uv run graphify update .                   # rebuild the knowledge graph
```

SUMO is provided by the `eclipse-sumo` Python wheel; no system install required.

## Working rules

1. **Plan before code.** Any change over ~30 LOC or any new module starts in plan
   mode: write the approach, get it reviewed, then implement. No code first.
2. **TDD.** Write the failing test before the implementation. Bug fixes add a
   regression test in the same commit.
3. **Small commits.** One logical change per commit, conventional commit messages
   (`feat:`, `fix:`, `test:`, `docs:`, `chore:`). Never mix refactors with features.
4. **Assumptions are first-class.** Every result-bearing feature must document its
   input assumptions. Never present simulated output as a real-world prediction.
5. **Benchmarks are reproducible.** Any number that appears in README or docs must
   be regenerated by a script under `evals/` or `scripts/`. No hand-picked results.
6. **Definition of done:** tests pass, `ruff` and `pyright` clean, docs updated,
   assumptions stated.
7. **Agent sources live in `agent/`.** Skills (`agent/skills/`), MCP servers
   (`agent/mcp.json`), and hooks (`agent/hooks.json`) are the single source of
   truth; per-tool files are generated. After editing a source run
   `uv run python scripts/sync_agent_config.py`; CI fails on drift.

## Domain rules

- Study area is defined by a bbox in `src/rushlab/config/areas.yaml`; adding an
  area is a skill (`add-study-area`) with a documented procedure.
- The border crossing is modeled as a capacity-controlled sink (lane types:
  General / Ready / SENTRI). Calibration targets: BTS monthly volumes, CBP
  historical wait times. See `docs/decisions/0001-scope.md`.
- Northbound focus for v0.1. The US side is out of scope; queues terminate at the
  boundary sink.
- Never commit raw OSM downloads; commit only the recon summaries in `data/raw/`.

## Knowledge graph

- The repo is indexed by Graphify (code-only, no API key). Rebuild with
  `uv run graphify update .`.
- Prefer `uv run --no-sync graphify query "<question>"` (scoped subgraph) over
  grepping raw files; `graphify-out/GRAPH_REPORT.md` is the broad architecture view.
- `graphify-out/graph.json` and `GRAPH_REPORT.md` are committed; `graph.html` and
  caches stay local. The `graphify` MCP server exposes graph tools to agents.

## Data sources

- OpenStreetMap (ODbL) — street network, signals
- BTS Border Crossing/Entry Data (public domain) — inbound volumes
- CBP Border Wait Times (public) — wait-time profiles and lane service rates
