# Five-minute demo script

For a screen-share interview: exact commands, what to say, and fallbacks. No
network access is required — everything reads committed caches or files.

## Pre-demo checklist (run 10 minutes before)

```bash
uv sync                      # environment ready
uv run rushlab --version     # prints 0.1.0
uv run python scripts/agent_doctor.py    # all checks pass
uv run rushlab analyze san-ysidro --top 5   # warms caches, prints bottlenecks
```

Have these open in tabs: `README.md`, `evals/RESULTS.md`,
`docs/reports/san-ysidro-signal-optimization.html`, `docs/INTERVIEW-MAP.md`.

**Fallbacks:** if `analyze` is slow, open `results/san-ysidro/analysis.json`
(regenerated by the command). If the HTML report fails to open, the same numbers
are in `evals/RESULTS.md` and the ADRs.

## Timed script

**0:00 — Frame it (20 s).** "RushLab answers what-if questions about the San
Ysidro border approach in Tijuana — and the way it was built is itself the
portfolio. Headline finding up front: the border port, not signal timing, is the
bottleneck."

**0:20 — Agent setup (30 s).** Show `AGENTS.md` and `agent/`.
"What you're seeing is one neutral definition: skills, MCP servers, and hooks
generate the native configs for opencode, Claude Code, and Codex. CI fails if
they drift, and the doctor verifies the whole setup."
Run: `uv run python scripts/agent_doctor.py`

**0:50 — Analysis (50 s).** Run: `uv run rushlab analyze san-ysidro --top 5`
"Straight from OpenStreetMap: 2,302 nodes, 5,665 edges, 130 signals. Betweenness
and bridge analysis ranks bottlenecks; min-cut shows capacity into the border.
Top bottleneck: Calzada Defensores de Baja California / Blvd Cuauhtémoc."

**1:40 — Demand calibration (40 s).** Open
`data/derived/san-ysidro/calibration.json`.
"Demand comes from official BTS counts — 43,057 personal vehicles a day — and CBP
wait snapshots. Capacity is a range, not a point estimate: 2,040 to 4,080 veh/h.
The committed snapshot series grows every time I run it; provenance is in the
file."

**2:20 — Simulation and the finding (60 s).** Open the committed HTML report.
"SUMO runs the 06:00–10:00 peak with a metered port entry. I retimed the eight
busiest signals with Webster plus a genetic algorithm over offsets — and
measured: throughput +3.5%, delay −0.7%, teleports slightly up. That's the
honest headline: at a bottleneck whose outflow is fixed by policy, upstream
green splits can't fix the queue. The useful levers are metering policy, lane
management, staggering, and rerouting — and the pipeline is ready for those."

**3:20 — Knowledge graph (40 s).** Run:
`uv run --no-sync graphify explain metering_program`
"Agents navigate this repo through a knowledge graph instead of grepping. Ten
real questions, measured with tiktoken: focused retrieval costs 90.7% fewer
tokens than grep-and-read, 20/20 symbols resolved. The graph is committed, so
it works offline."

**4:00 — Agent tooling (30 s).** Show `agent/mcp.json` and the tool table in
README.
"The project ships its own MCP server — eight typed tools — so any of the three
agents can drive the whole pipeline: analyze, calibrate, simulate, optimize,
report. Long runs require explicit confirmation."

**4:30 — Benchmarks and limits (20 s).** Open `evals/RESULTS.md`.
"All three claims are recorded: token reduction, plan-vs-execute cost, skill
efficacy. They're n=1 indicators with the model named — not statistics, and I say
so in the ADR."

**4:50 — Close (10 s).** "The repo is public, CI is green, and every number
regenerates with one command. The fastest way to judge this is to run it."

## Q&A appendix

1. **"Why did signal optimization barely help?"** The metered port caps outflow
   at ~2,720 veh/h while peak demand is ~4,150 veh/h; queues are structural.
   Measured: +3.5% throughput, −0.7% delay. ADR-0006.
2. **"Is this a calibrated traffic model?"** No — a scenario ranking under
   documented assumptions. Ranges, teleports, and a demand factor are reported,
   not hidden. ADR-0005.
3. **"How do you know the volumes are real?"** BTS Socrata API, port 2504,
   vintage 2026-07; CBP snapshots are committed with timestamps.
   `data/derived/san-ysidro/`.
4. **"Hardest implementation trap?"** Forcing a port signal with `--tls.set`
   while injecting a program via `--tllogic-files` fails on ordering — solved by
   patching the generated net. Also: TLS offsets can't be set via TraCI in 1.27,
   so the GA evaluates patched nets in parallel. ADR-0005/0006.
5. **"How does the multi-agent setup stay in sync?"** One source under `agent/`,
   generated outputs, CI drift check, doctor script. ADR-0002/0007.
6. **"What did the benchmarks actually prove?"** Focused graph retrieval is
   ~10× cheaper in context tokens; planning costs ~2× on small tasks; skills buy
   convention adherence at ~1.9× tokens. All n=1. ADR-0008.
7. **"What's next?"** Policy scenarios: port metering split, Ready/SENTRI lane
   management, departure staggering, Otay Mesa reroute share; accumulate the CBP
   snapshot series for a measured hourly profile.
8. **"What isn't covered?"** Residential streets, pedestrians, southbound
   traffic, the US side beyond a stub; and audio/DSP plus telecom live in my
   other experience, not here.
